### 2. AI 抽出・要約

- **流れ**：`select-ai-targets.mjs`（選ぶ）→ `fetch-docs.mjs`（公告・添付を取得し pdftotext / textutil でテキスト化）→ Claude Code が読んで `data/ai/results/{id}.json` を書く → `import-ai.mjs`（検証して case_ai・case_tags に入れる）
- **締切の判断（選定時）**：API の入札書提出期限があるのは全体の1%程度しかないので、公告文の「提出・締切・開札・入札・申請・受付・期限」の直後にある日付（和暦・全角を正規化）の最も遅いものを締切とみなした。履行期間・納入期限の日付は除外。11/10〜120日後のものを候補にした（3,730件）
- **偏りの抑え方**：都道府県（重み3）・業種（重み1）・種別（重み0.2）の、すでに選んだ件数が少ないものを優先する貪欲法。結果は47都道府県すべて2〜3件
- **読み手**：「あなた（Claude Code）が1件ずつ読む」は、10件ずつ10のサブエージェント（同じ Claude Code）に並列で読ませた。共通の手順書は `data/ai/INSTRUCTIONS.md`。書いたのは JSON だけで、検証は `import-ai.mjs` が行う
- **差し替えた10件**：国の機関の案件の一部は、API の公告URLが調達ポータルの検索画面（`p-portal.go.jp`）で、公告本文が取れなかった。この10件の要約は API の値の言い換えにしかならないので取り込まず（`data/ai/results-rejected/`）、資料が読める別の10件と差し替えた。以後、調達ポータルのリンクしかない案件は選定で除外する
- **case_ai の形**：既存の `qualifications` / `bid_method` / `summary` 列に加え、`extracted`（JSON：種別・業種・各期限・開札日・履行期間・資格・入札方法・履行場所・正しい件名）と `source_files`（読んだ資料の URL）を追加（0004）。業種タグは case_tags に `method='ai'` で入れ、その案件のキーワードタグは外す
- **表示**：API の値が空の項目だけ AI の値で埋め、「公告から抽出（AI）」を付ける。参加申請の期限・入札方法・必要な資格は API に無いので常に AI（ラベル付き）。要約は「AIによる要約」の見出しと注意書き付き。件名を補正した案件は、補正後の件名を見出しにして「官公需情報ポータルサイト上の件名は『…』です」と併記
- **AI のサイト表示を見送ったもの**：サブエージェントの `notes`（判断メモ）はサイトに出さない

#### 読んだ結果わかったこと

- **締切が過ぎていた**：参加申請の期限が 11/5 より前だったものが約15件（入札書の提出期限は先）。選定時の推定は「最も遅い日付」なので、入札書の期限で判定され、参加申請の期限は見ていなかった。入札書の期限まで過ぎていたのは2件（岡山市の舗装工事、石川県の3Dスキャナー）
- **API の発注機関と公告の発注者が食い違う**：法務局の案件3件（API は横浜・前橋・新潟、公告は宇都宮地方法務局）、関東財務局の1件（API は埼玉県、発注は東京財務事務所）。官公需ポータル側の紐付けの問題とみられる。表示は API の値のまま

- **入札方法（紙・電子）**：「電子が原則で、承諾すれば紙も可」を `electronic` とするか `both` とするかがバッチで揃っていない
- **資料の不足**：仕様書がログイン制・メール請求・ZIP のため読めず、履行場所や期間が null になった案件がある

### 3. 回遊性

- **URL**
  - `/prefectures`：都道府県一覧（地方別）
  - `/gyoshu`、`/gyoshu/{slug}`：全国の業種別。都道府県で絞るリンク付き
  - `/{pref}/gyoshu/{slug}`：都道府県×業種
  - `/orgs/{org_id}`：発注機関
  - 既存の `/{pref}/{slug}`（種別 or 市区町村）はそのまま
  - 業種を `/{pref}/{slug}` に混ぜず `gyoshu/` を挟んだのは、市区町村のスラッグとの衝突を避けるため。`gyoshu`・`orgs`・種別名は市区町村スラッグの予約語にしてある
- **業種タグは全案件にキーワードで付けた**：指示は「100件を AI で」だったが、AI のタグだけでは業種ページがほぼ空になり、関連枠も働かない。そこで全案件に件名キーワードのタグ（`method='rule'`）を付け、AI で読んだ案件だけ AI のタグに置き換えた。業種ページには「件名のキーワードから自動で分類」と注記している。タグなしは約26%（件名が「入札公告」やファイル名のもの、売払い、研究用の特殊な機器など）
- **発注機関ページ**の見出しは API の機関名そのまま。同じ名前が複数の都道府県にある場合は、件数が多い県をパンくずに使う。表記ゆれで機関が分かれることはページに注記
- **都道府県ページ**に「業種から探す」と「発注機関から探す」（件数の多い30機関）を追加。市区町村は案件のあるものだけ表示するように変えた（全国化で空の市区町村が多数並ぶため）
- **案件詳細の下の3枠**：同じ発注機関／同じ市区町村／同じ都道府県×同じ業種（最初のタグ）を各5件。案件が無い枠は出さない
- **一覧の各行**：発注機関・市区町村・業種（都道府県×業種）へのリンクを付けた
- **ヘッダー**：都道府県から探す／業種から探す／入札の基礎知識／検索欄。**フッター**：解説記事・探し方・固定ページの3列
- トップは都道府県ごとに10件ずつ並べる形（47回のクエリ）をやめ、都道府県・業種の入口と全国の新着20件にした

### 4. 検索

- `/search?q=&pref=&category=&tag=&open=1`。キーワードは空白区切りで最大5語、各語を件名・発注機関・公告文のどれかに含む（AND）。D1 の LIKE
- 「締切前の案件だけ」は、入札書の提出期限（API、なければ AI 抽出）が今日以降のもの。**期限が分からない案件は含まれない**（API で期限があるのは全体の1〜2%程度なので、ほぼ AI で読んだ案件だけになる）。画面に注記した

### 6. エッジキャッシュ

- Astro 7 に組み込みの「ルートキャッシュ」（`routeRules` ＋ `@astrojs/cloudflare/cache` の `cacheCloudflare()`）と、Workers のキャッシュ（`wrangler.jsonc` の `"cache": { "enabled": true }`）を使った。自前の Cache API 実装は不要だった
  - 一覧（トップ・都道府県・市区町村・業種・発注機関）：10分（期限切れ後5分は古いものを返しつつ裏で更新）
  - 案件詳細：1時間（同10分）
  - 検索：キャッシュしない
- **同期後の更新**：`pnpm sync:d1` の最後に `POST /api/cache-purge`（Bearer トークン）を呼び、キャッシュを全消去する。トークンは `.dev.vars` に生成済み。**リモートの secret 登録は権限の都合で私からは実行できなかった**（下の「判断してほしいこと」）。未登録の間は消去が 403 になり、最大1時間古い表示が残る
- デプロイすると Worker のバージョンが変わるため、キャッシュは自動的に入れ替わる（`cross_version_cache` は既定の false）

## 判断の記録

### 締切の判断（AI 抽出の対象選び）

- `scripts/select-ai-targets.mjs`：「参加申請の期限」と「入札書の提出期限」の**早いほう**で判断するように変えた
  - 公告文で日付の直前に「申請・参加表明・申込・資格確認・参加意向」があれば参加申請の期限、「入札書・提出・締切・開札・入札日・受付」なら入札書の提出期限の候補
  - それぞれ最も遅い日付を採り、両方あれば早いほう。入札書の提出期限は API の値があればそれを使う
  - 候補は 3,105件 → 2,322件に減った（参加申請の期限が先に来る案件が除かれるため）

### AI の判断基準の見直し

- `data/ai/INSTRUCTIONS.md` を改訂し、`data/ai/REVISE_2026-11-05.md` の手順で100件の `bid_method` と `project_name` だけを読み直した（5つのサブエージェント×20件）
- **入札方法**：電子のみ（`electronic`）／電子・紙どちらも可（`both`）／紙のみ（`paper`）の3択に固定
  - 「電子が原則で、承諾・届出・申請により紙でも参加できる」は**どちらも可**に入れた。紙で参加する道があるため
  - 結果：紙のみ 47／どちらも可 33／電子のみ 11／不明 9（読み直しで electronic → both が20件）
  - 画面の表示も「電子のみ」「電子・紙どちらも可」「紙のみ（持参・郵送など）」に変えた
- **件名の補正**：API の件名がファイル名・日付だけ・「入札公告」だけ・案件と無関係な文など、**明らかに壊れている場合だけ**
  - 「(PDF 171KB)」付き、「〜の実施について」などは API の値のまま
  - 29件 → **1件**（「計算書作成例を参照してください」が件名になっていた久留米市の工事）
  - 奈良県警の1件は、API の件名が公告の委託名と別の名前だった（形としては壊れていない）。基準どおり API の値に戻した

### 公告文の全文を R2 に

## 判断したこと

- **「となりの市町村」**：隣接のデータは持っていないので、同じ都道府県で件数の多い市町村（上位8）で代用した。見出しの下に「◯◯県で仕事の多い市町村です」と注記。都道府県ページでは同じ枠を「市区町村から探す」（すべての市区町村）にした
- **件数のタイル**：見本の「今受けられる仕事」は「掲載中の仕事」にした。締切が分かる仕事は全体の2%ほど（API の提出期限は 7,144件中80件、ほかは AI で読んだ100件）しかなく、「今受けられる」かどうかは大半で判断できないため
  - 「今週新しく出た仕事」（公告日が直近7日）と「締切まで7日以内」（次の締切＝参加申請・入札書の提出のうち早い方が7日以内）は、同期のときに計算して `case_counts` に入れる（dim `week` / `due7`）。ページは読むだけで、「◯月◯日時点」と注記する
  - 市区町村の「業種から探す」と「よく発注する機関」用に、市区町村×業種・市区町村×発注機関の件数も同期で計算する（dim `city_tag` / `city_org`、主キーの範囲で読む）。合わせて約3,300行。明日の同期は 31,479文（前回の見積もりより約3,300増）、統計を含めても書き込みは約4万行の見込み
- **締切が近い仕事**：締切が分かる仕事が少ないので、市区町村ページは「締切が近い仕事」（締切が分かり、今日以降のもの。無ければ出さない）と「新しく出た仕事」（新着10件。上に出たものは除く）の2段にした
- **並び順「締切が近い順」**：締切が分かる仕事だけを表示し、その旨を注記した。期限の部分インデックス（数百件）から読むので、ほかの条件の列には `+` を付けてインデックスに使わせない
- **件数を数えない一覧**：集計テーブルで件数が分からない組み合わせ（ラベル・業種×市区町村・締切など）は、D1 で COUNT せず「◯件以上」と出す（1件多く取って次のページの有無だけを見る。検索と同じやり方に揃えた）
- **絞り込んだ一覧は noindex**：ページ送り以外のクエリ（市区町村・ラベル・業種・締切前・並び順）が付いた一覧はすべて noindex（従来のラベルと同じ扱いを広げた）
- **トップから移動しない場合**：DESIGN.md の `?home=1` に加えて、サイト内から戻ってきたとき（リファラーが同じサイト）も移動しない。ロゴ・パンくずのリンクは `/` のまま（URL を増やさない）。`/?home=1` には canonical `/` を付けた
- **ヘッダー**：見本どおり3種類（トップ：メニューのみ／地域ページ：地元ピル・その地域の検索窓／それ以外：検索窓＋検索ボタン・メニュー）。地域ページの検索窓は、その都道府県・市区町村で絞った検索になる（検索に `city` を追加）。スマホではロゴとお気に入りを1行目、地元ピル、検索窓の順
- **フッター**：DESIGN.md の「フッターの帯＝掲示板の面」に合わせて全ページ生成り濃いめの帯にした（詳細・一覧の見本は古い白いフッターだったため）。官公需APIの出典の注記は残した
- **広告枠**：見本の「広告枠（300×250）」は、AdSense を入れるまで空の枠を出すと見栄えが悪いので出していない。市区町村ページの横は代わりに「◯◯の仕事を絞り込む」（一覧への導線）を置いた
- **案件詳細の要約のチェックリスト**：見本の4項目のチェックリストに当たるデータ（要点の箇条書き）は AI の抽出に無いので出していない。要約の本文と「参加のポイント」だけ
- **案件詳細の「水戸市で今受けられる仕事」**：受付中かどうかが大半で分からないので「水戸市のほかの仕事」にした。「この機関の入札」「◯◯県の◯◯の仕事」も横に置いた
- **日程の時系列**：公告・参加申請・質問・入札書の提出・開札・履行期限のうち、分かるものを日付の順に並べる（公告によって質問の期限が参加申請より前のことがあるため）。済んだ段階・次の段階・「あと◯日」はブラウザで決め直す
- **タブの順**：見本どおり すべて・工事・物品・役務。タブを切り替えても絞り込みの条件は引き継ぐ
- **案件カードの☆**：見本の 44px の四角いボタン。登録済みは柿の薄い面と塗りつぶしの☆
- **地元の選択の市区町村**：案件の無い市区町村も選べる（地元はそこにある）。`/api/cities` は主キーの範囲で、その都道府県の市区町村の行だけを読む

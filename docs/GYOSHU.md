# 業種タグの体系

じもと入札では、案件に「業種タグ」を付け、業種ページ（`/gyoshu/{slug}`、`/{都道府県}/gyoshu/{slug}`）や関連案件で使います。
定義の正本は [src/lib/gyoshu.ts](../src/lib/gyoshu.ts)（サイトとスクリプトの両方が読む）。この文書はその説明です。

## 考え方

- **利用者が「自社でできる仕事」を探す単位**で分ける。官公需APIの種別（物品・工事・役務）より細かく、入札参加資格の営業種目（数十〜百以上）より粗い
- 29種類。工事5・役務14・物品10。1案件に1〜3個
- 名前は「清掃」「警備」のように、事業者が自社の業種として名乗る言葉にする
- 「その他」は作らない。どれにも当てはまらない案件はタグなし（種別・地域・発注機関からは辿れる）

## 付け方（2通り）

| 方法 | `case_tags.method` | 対象 | 内容 |
|---|---|---|---|
| キーワード | `rule` | 全案件 | 件名（NFKC 正規化）にキーワードが含まれるか。種別が分かる案件は、その種別向けのタグだけを見る。最大3個（並び順が先のタグを優先）。`scripts/tag-cases.mjs` |
| AI | `ai` | 公告を読んだ案件 | 公告・添付資料を読んで1〜3個。AI のタグがある案件はキーワードのタグを使わない。`scripts/import-ai.mjs` |

キーワードの判定は粗いので、サイトでは「件名のキーワードから自動で分類」と注記している。

## 迷いやすい境界

| ケース | 付けるタグ |
|---|---|
| 設備の新設・更新工事 | 工事のタグ（電気・通信工事／管・空調設備工事） |
| 設備の定期点検・保守・小修繕（役務） | 設備の保守・点検 |
| システムの保守・運用 | システム開発・運用（「設備の保守・点検」は付けない） |
| パソコンの購入 | パソコン・IT機器。リースなら「賃貸借・リース」も |
| 指定管理・施設の総合管理 | 施設管理・運営（清掃・警備を含んでいても、包括的な委託ならこちら） |
| 橋梁点検・道路の点検診断 | 測量・設計 |
| 草刈り・樹木の剪定（役務） | 造園・草刈り・樹木管理 |
| 給食の調理業務の委託 | 食料品・給食 |
| 健診・検診の委託 | 医療・医薬品 |

## 変えるとき

1. `src/lib/gyoshu.ts` を直す（slug を変えると URL が変わるので、変えるなら旧 slug からのリダイレクトを用意する）
2. この文書の一覧を更新する
3. `node scripts/tag-cases.mjs` でキーワードのタグを付け直し、`pnpm sync:d1`

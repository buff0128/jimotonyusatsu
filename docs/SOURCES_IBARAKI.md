## ① いばらき電子入札共同利用 入札情報公開サービス（建設工事・コンサル）

### 画面の流れ

ポータル（静的HTML）から「ログイン」を押すと、JavaScript の `window.open` で別ウィンドウが開く。以降はすべて Struts（`/koukai/do/*Action`）の画面で、Shift_JIS（Windows-31J）、フレーム構成。

| 手順 | リクエスト | 内容 |
|---|---|---|
| 1 | `GET /koukai/do/KF001ShowAction` | セッション（`JSESSIONID`、Path=/koukai）が発行される。調達機関の選択肢と、部局・課所の対応表（JSの配列 `p1/p2/q1/q2`）が入っている |
| 2 | `POST /koukai/do/KK000ShowAction` | `hachukikan`（機関コード例 `0201ZZZZZZ`＝水戸市）、`supplytype`（`00`工事／`01`コンサル）。フレームセットが返る。**機関を空にすると「システムエラー」**になり、全機関の一括検索はできない |
| 3 | `POST /koukai/do/KK301SearchAction` | 発注情報の検索。`date_start`／`date_end`（公開年月日 `YYYY/MM/DD`）、`A046`（入札方式）、`koujimei`（工事名）、`koujibasho`（工事場所）、`A300`（表示件数 `040`＝100件） |
| 4 | `GET /koukai/do/KFK301FrameShow` | 検索結果の一覧（iframe）。条件と結果はセッションに保存されている |
| 5 | `GET /koukai/do/KK301SearchAction?page=N` → 4 | ページ送り（セッション依存） |
| 詳細 | `POST /koukai/do/KK302ShowAction?control_no=…` | 詳細。**セッションが無いと「タイムアウト」**になり、固定URLとしては使えない |
| 添付 | `KK302DownloadAction?control_no=…&fileflg=N` | 公告PDF・説明書・図面など（試作では取得していない） |

- 一覧のセルの多くは `<script>` 内の `tableFormat('値', 桁数)` で書き出されている（素のHTMLには値がない）。試作では JS を動かさず、引数の文字列を正規表現で取り出している
- 部局・課所は指定しなくてよい（指定しなければ、その機関の全部局が対象）
- 運用時間は24時間（ポータルの記載）。ただし共同利用ポータルのトップには「午前0〜3時は停止」とも書かれている

## 取得の難しさ

1. **セッションと画面遷移に依存している**：URLを直接叩いても結果は取れず、入口 → 機関選択 → 検索 → iframe の順に踏む必要がある。ページ送りもセッションに保存された検索条件を使う
2. **①は全機関の一括検索ができない**：35機関×2区分を順に検索するため、1回の取得で約160リクエスト（2.5秒間隔で約7分）。毎日回すなら許容範囲だが、件数が0の機関にもリクエストが飛ぶ
3. **Shift_JIS**：応答のデコードは Node の `TextDecoder('shift_jis')` でできる。ただし Node には Shift_JIS のエンコーダが無いので、日本語を POST できない。試作では日本語の hidden（表示用の機関名）を空で送っており、検索結果には影響しなかった。工事名でキーワード検索したくなったら `iconv-lite` などが必要になる
4. **値の一部が JavaScript で書き出される**（①）：`tableFormat('…')` の引数を正規表現で取り出している。画面の作りが変わると壊れやすい。見出しの文字列で列を対応づけ、知らない見出しが出たら警告するようにしてある
5. **固定URLがない**：詳細も添付もセッション経由でしか開けない。サイトからは案件ごとにリンクできない（規約上も直接リンクは禁止。後述）
6. **公告PDFの中身**：入札期限・参加資格・入札方法は PDF の中にしかない。KKJ と同じく、PDFのテキスト化（poppler）と抽出が必要
7. **重複**：KKJ にも同じ案件が載ることがある（今回6件）。今は別の行として入っているので、「機関（市町村）＋件名＋公告日」で同一とみなすなどのまとめ方を決める必要がある

## 規約上の注意

### ① 茨城県建設工事等電子入札システム利用者規約（平成18年12月4日変更）

出典：http://ppi.cals-ibaraki.lg.jp/downloadfiles/kiyaku.pdf
ポータルの説明では、「茨城県建設工事等電子入札システム」は電子入札システムと入札情報サービスの**総称**とされている。そのため、この規約は入札情報サービスにも適用されると読むのが自然。

- 第2条：システムを利用した時点で規約に同意したものとみなす
- **第4条(1)：システムを本来の目的以外の用途に利用することの禁止**。機械的な収集と転載が「本来の目的」に入るかは書かれていない
- **第4条(6)：共同利用センターに無断でシステムへ直接リンクすることの禁止**。案件ページへのリンクは無断ではできない。ポータル（静的なトップページ）へのリンクがこれに当たるかも、確認したほうがよい
- **第11条：システムが提供するプログラムその他の著作物の修正・複製・改ざん・販売等の禁止**（著作権は茨城県）。件名・日付・金額などの事実は著作物に当たらないと考えられるが、公告PDF・仕様書・図面などの添付は著作物になりうる。転載・再配布は避けるべき
- 第13条：規約は予告なく変更されうる

### ② 茨城県電子調達システム 入札情報サービス

- 利用規約や二次利用に関するページは見つからなかった（県の「システムの入口」ページ、「要綱・要領」ページ、茨城県電子調達実施要領を確認）
- 実施要領 第8条：一般競争入札の公告は電子調達システムで行う。第30条：結果は入札情報サービスに登録し、すべて公開する。公開すること自体は前提になっている
- 茨城県ホームページの一般的なサイトポリシー（著作権・リンク）が当てはまる可能性があるが、未確認

### サイト設計での前提（今回の依頼どおり）

- **表示するのは事実の項目だけ**：件名、機関、公開日、開札日、予定価格、工種、場所、入札方式。工事概要・備考は短い事実の記載なので出してよいと考えるが、規約確認の結果しだい
- **添付ファイル（公告PDF・仕様書・図面）は転載しない**。取得するとしても、手元での抽出（期限・資格の読み取り）にとどめる
- **公式へのリンクは各システムの入口ページへ**（案件ページへの直接リンクはできない）。①は第4条(6)があるので、入口ページへのリンクも事前に確認したい
- 出典表記：今の案件詳細ページは出典を「官公需情報ポータルサイト」で固定している。PPI 由来の案件を出すときは、`source` に応じて出典とリンク先を切り替える必要がある

### 問い合わせ先（ポータル・県サイトの記載）

- ①：茨城県建設CALS/EC共同利用センター（ポータルの「お問合せ」ページ）
- ②：茨城県 会計事務局 指導室（調達担当）、または電子調達システムヘルプデスク 0296-71-8033

## 試作スクリプト

```sh
export PATH=/opt/homebrew/bin:$PATH
pnpm fetch:ppi                                        # 両方・今日を除く直近3平日
pnpm fetch:ppi -- --system koji --from 2026-10-30 --to 2026-11-04
pnpm fetch:ppi -- --system koji --org 0201ZZZZZZ      # 機関を絞る（試験用）
```

- `scripts/fetch-ppi.mjs`：手順を進めて一覧を読み、`cases` に upsert する。詳細ページと添付は取りにいかない
- `scripts/lib/ppi.mjs`：Cookie を持ち回るセッション（1本ずつ、間隔2.5秒）、Shift_JIS のデコード、一覧のパース。「タイムアウト」「システムエラー」のページを検出したら、セッションを作り直して1回だけ再試行する
- 生HTMLは `data/raw/ppi/{source}/{from}_{to}/` に保存（今回は2.8MB）
- 既定の期間は「今日を除く直近N平日」で、**祝日は考慮していない**。祝日をはさむときは `--from/--to` で指定する
- `migrations/0003_case_sources.sql`：`kkj_key` → `source_key` に改名し、`source`・`case_number`・`estimated_price`・`work_type` を追加。テーブルを作り直すと `case_ai` が CASCADE で消えるため、ALTER TABLE だけで済ませている（旧列の UNIQUE は残る）
- `scripts/sync-d1.mjs`：`source = 'kkj'` の行だけを D1 に送るようにした（PPI 由来のデータが誤って公開されないように）。**次に D1 へ同期する前に `pnpm db:migrate:remote` で 0003 を適用すること**。適用しないと列名が合わずに失敗する

今回の取得の記録：調査で約40リクエスト（すべて2.5秒以上の間隔）、本取得で①158＋②7×2回。

## 次に決めること

1. ①②の運営者に、取得・転載・リンクの可否を問い合わせるか（する場合は問い合わせ文を用意します）
2. KKJ との重複のまとめ方（どちらの行を正とするか。①②のほうが開札日・予定価格を持っている）
3. 公告PDFを取得して、入札期限・資格を抽出するか（poppler の導入と、添付のダウンロードが必要。規約確認のあとが安全）
4. ①の取得頻度：毎日1回なら約160リクエスト。件数のあった機関だけ毎日、ほかは週1回にするなど、間引くかどうか
